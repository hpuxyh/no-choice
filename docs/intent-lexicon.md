# 意图词库 + 餐厅映射表

> 用途:把用户口语化的需求("吃点清淡的"、"吃完一身味受不了"、"健身餐")映射成
> **搜什么(search)** 和 **排除什么(avoid)**,再加上 **口味/场景/健康标记**。
> 词库尽量贴近大众点评/外卖评论里大家真实的说法,含同义/口语变体,方便正则匹配。
>
> 对接现有引擎概念:
> - `search` → 拿去高德搜的关键词(对齐 `FOOD_SEARCH_TERMS` / `TAG_SEARCH_KEYWORDS` 能搜到的词)
> - `avoid`  → `avoidKeywords`(**硬过滤**,店名/品类命中即剔除,永不放宽)
> - `taste`  → 口味标记(清淡/重口/健康…)
> - `scene`  → 场景标记(约会/商务/一人食…)
> - `note`   → 难在 POI 层精确处理、建议"下单备注"或给用户提示的项

匹配优先级建议:**否定/忌口 > 健康 > 温度口感 > 口味 > 场景 > 食量价位**(越靠前越"硬")。

## 勘误 / 待修(读现有 `choiceData.js` 发现)

1. **`DIET_EXCLUDE_KEYWORDS["海鲜忌口"]` 含 `"潮汕牛"` —— 这是 bug。**
   潮汕牛肉火锅是**牛肉**,不是海鲜。当前"不吃海鲜"会误杀潮汕牛肉锅。
   建议改为:`["海鲜","海产","生蚝","生猛海鲜","海鲜自助","潮汕海鲜","舟山海鲜","鱼生","刺身"]`。

2. `MEETUP_DIET_OPTIONS` 里的"清真/素食/不吃香菜"目前只是 chip 文案,
   POI 层没有对应排除/认证逻辑。香菜属"下单备注"级,清真/素食应升级为正向筛选(只搜认证类)。
